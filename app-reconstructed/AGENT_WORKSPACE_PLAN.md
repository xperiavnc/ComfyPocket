# Agent 项目与会话管理方案

- 状态：待实施
- 编写日期：2026-10-20
- 工程：`app-reconstructed`
- 范围：Agent 页面布局、项目与会话管理；不改主底栏的样式、位置或切换行为
- 设计参考：`agent-page-ui-v4.html`、`agent-projects-layout-v2.html`、`agent-sessions-delete.html`（本地 UI 方案稿）

## 1. 目标

把 Agent 从单一、持续增长的聊天页，改为由项目和独立会话组成的工作区。用户可以创建项目、在项目中管理多段对话、快速恢复最近会话；会话长按后可删除。当前绘图和 Chat 能力、工作流选择、提示词展示、生成媒体预览及 Agent 设置继续保留。

项目承担长期上下文，会话承担一次具体任务的消息、附件和生成记录。项目功能是本次范围的一部分，不是可选项。

## 2. 当前工程基线

- Agent 主页面在 `app/src/main/java/com/comfyui/mobile/ui/screens/AgentScreen.kt`，聊天列表和输入区在 `ui/screens/agent/AgentChatPanel.kt`。
- `AgentChatMessage` 已包含消息正文、附件、澄清问题、正反向提示词及角色选择等信息，可沿用作会话消息的数据载体。
- `MainViewModelAgent` 目前用按运行环境命名空间隔离的 SharedPreferences JSON 保存一份消息列表（`agent_messages__<scope>`），并单独保存最近生成媒体与提示词状态；还没有项目或会话实体。
- Agent 请求由 `AgentSessionController` 管理单轮运行状态。会话切换必须与运行中的请求协调，防止迟到的回调写入另一个会话。
- 工程已有悬浮底栏安全间距机制 `LocalFloatingNavClearance`。新页面、抽屉或底部面板都必须保留此间距，不得遮挡底栏。
- 当前工程未配置 Room。多项目、多会话和大量消息适合迁移到有明确 schema/version 的本地数据库；引入 Room 与 KSP/KAPT 的构建配置属于实施阶段工作。

## 3. 页面结构

### 3.1 Agent 对话页

- 顶栏继续显示 Agent 标题、当前工作流/角色配置入口及设置入口。
- 增加清楚但紧凑的当前上下文入口，显示“项目名 / 会话名”；点按打开项目与会话工作区。未归入项目时显示“未归入项目”。
- 保留 Chat/绘图模式、模型配置、最近生成入口、对话内容和底部输入区。长标题截断，不挤压主要控制项。
- 底栏维持现有实现，不调整图标、选中态、布局、动画或路由。
- 工作区以 Agent 页面内的抽屉或全屏子页面承载，不在聊天内容区域常驻大块项目面板。

### 3.2 项目与会话工作区

- 顶部提供搜索，以及“新建项目”和“新建会话”入口。
- 项目列表项显示项目名、说明摘要、会话数量和最近更新时间；提供打开、编辑、归档/删除操作。
- “最近会话”区域按更新时间倒序展示最近对话，标明所属项目或“未归入项目”、时间及简短消息预览。
- 打开项目后显示项目说明、可配置的项目指令/参考资料入口、项目会话列表和新建会话入口。
- 项目列表与最近会话共用同一工作区，避免在 Agent 主页面同时堆叠多组卡片。
- 空项目、无会话、搜索无结果均提供明确空状态和直接创建入口。

### 3.3 会话操作

- 点按会话立即恢复该会话，并恢复其消息、模式、会话级生成记录和必要的工作流上下文。
- 长按会话进入选中态，显示“删除会话”操作；同时提供可访问的更多菜单，避免把长按作为唯一入口。
- 删除前展示会话标题和影响说明，并要求二次确认。删除聊天记录及会话关联索引；不删除已经保存到应用媒体库/服务器上的实际图片或视频文件。
- 删除当前会话后，切换到最近的其他会话；没有其他会话时显示空白新会话状态。
- 新建会话默认归属当前项目；从工作区顶层新建时允许选择项目或保持“未归入项目”。

## 4. 数据模型与持久化

### 4.1 建议实体

| 实体 | 核心字段 | 说明 |
| --- | --- | --- |
| `AgentProject` | `id`、`scope`、`name`、`description`、`instructions`、`defaultWorkflowRef`、`createdAt`、`updatedAt`、`archivedAt` | 项目长期资料；首版名称必填，其余按需配置 |
| `AgentConversation` | `id`、`scope`、`projectId?`、`title`、`mode`、`llmProfileId?`、`workflowRef?`、`createdAt`、`updatedAt`、`lastMessagePreview` | 单次任务上下文与列表元数据 |
| `AgentMessage` | `id`、`conversationId`、`sequence`、`payloadJson`、`createdAt` | `payloadJson` 使用现有 `AgentChatMessage` 结构，保留旧字段兼容 |
| `AgentConversationMedia` | `conversationId`、`mediaKey`、`createdAt` | 会话到生成结果的关联；不复制或拥有媒体文件 |

`scope` 延续当前 `local` / 云端命名空间隔离，项目和会话不得跨运行环境混用。生成请求的 LLM profile、模式及工作流引用按创建会话时的选择记录；需要时用户可在会话内显式切换。

### 4.2 持久化建议

- 使用 Room 保存项目、会话索引、消息和媒体关联；消息列表按 `conversationId` 分页/排序读取，避免把所有历史反复序列化进一个 SharedPreferences 字符串。
- 新增 Repository/Store 边界，由 ViewModel 暴露 `StateFlow`；Compose 页面不直接读写数据库或 SharedPreferences。
- 数据库操作放 IO dispatcher；删除、切换和迁移应有明确事务边界。
- 继续将现有角色档案、提示词设置、工作流绑定等全局配置保留在原作用域设置中。项目指令是额外上下文，不覆盖用户全局设定；会话消息不写入全局 prompt 设置。
- 将项目/会话数据库纳入应用备份和恢复流程，或在数据库迁移阶段同步扩展现有备份格式；恢复后校验引用缺失和重复 ID。

## 5. 旧数据迁移

- 首次启动新存储时，逐个 `scope` 检测 `agent_messages__<scope>`、`agent_latest_media_list__<scope>` 和对应提示词状态。
- 若旧聊天非空，为其创建一条 `projectId = null` 的迁移会话，保留原消息顺序、时间戳、附件、正反提示词、澄清问题和角色选择信息；关联旧生成记录。
- 迁移使用版本标记并可重复执行：先写入新存储、校验消息数与关键字段，再标记完成。校验成功前不删除旧键。
- 空旧聊天不创建无意义项目或历史会话；新用户首次进入时显示创建项目/会话入口。
- 如果迁移失败，继续读取旧数据并展示可重试状态，避免聊天记录消失。

## 6. 请求生命周期与隔离

- 发送任务时捕获不可变的 `conversationId`、`scope` 和运行配置；所有消息追加、生成记录关联和完成回调都显式携带该 ID。
- 会话切换时若 Agent 正在生成，先停止本轮并等待运行身份失效后再切换；提供明确的处理中反馈。禁止直接把正在运行的消息列表替换成另一个会话。
- `AgentSessionController` 的 turn identity 校验继续保留，并增加对会话 ID 的校验，避免迟到回调污染新会话。
- 切换项目只改变当前上下文，不隐式移动或删除会话；移动会话是单独、可撤销的操作。
- 删除或归档当前项目时，先展示项目内会话数量。删除项目不得静默连带删除会话；首版采用归档项目，项目下会话保留并可从归档入口恢复或移出。

## 7. 分阶段实施

### P1：存储与迁移

- 添加 Room schema、DAO、Repository 和 ViewModel 状态。
- 实现旧消息及媒体关联的一次性迁移与迁移回归测试。
- 先接入单一会话读写，确认现有 Agent 生成、附件、澄清和提示词行为不变。

### P2：会话管理

- 增加新建、命名、恢复、搜索、最近排序和长按删除。
- 增加确认删除、空状态和更多菜单操作。
- 校验会话隔离以及生成中切换/停止行为。

### P3：项目管理

- 增加创建、编辑、打开、归档和恢复项目。
- 增加项目内新建/移动会话，以及“未归入项目”列表。
- 接入项目说明和可选项目指令；项目指令拼接顺序需有单元测试，确保全局设置仍有效。

### P4：页面整合与备份

- 将项目/会话工作区接入 Agent 页面，按设计稿整理密度与层级。
- 验证小屏、长标题、键盘弹出、悬浮底栏安全间距和返回行为。
- 扩展应用备份/恢复，并对旧版本备份格式保持兼容。

## 8. 验收标准

- 可创建、编辑、打开和归档项目；项目列表显示最近活动和会话数。
- 可在项目中创建多段会话；会话可独立恢复消息、附件、提示词与生成记录，互不串线。
- 未归入项目的旧会话仍可访问；升级迁移前后的消息数量及关键字段一致。
- 长按会话可进入明确的选中态并删除；更多菜单提供等价入口；删除需确认且不会删掉已保存的实际媒体文件。
- 正在生成时切换会话不会串写；已停止会话的迟到回调不会更新当前会话。
- 项目归档不丢会话；项目删除/归档操作清楚展示影响范围。
- Agent 的绘图、Chat、附件、澄清问答、正反提示词、角色触发词、工作流绑定及最近生成预览均通过回归验证。
- 底栏视觉与行为完全不变；聊天输入、列表和工作区可滚动区域不会被悬浮底栏遮挡。
- Room 迁移、数据备份恢复、空状态、删除、隔离和请求竞态测试通过；Debug APK 可成功构建。

## 9. 暂不纳入

- 项目协作、云端同步、多设备冲突合并。
- 项目成员/权限系统、项目分享。
- 自动将所有历史聊天智能归类到项目。
- 删除会话时清理服务器或媒体库原始文件。
- 重做应用底栏或改变 Agent 与其他主页面之间的切换动画。
