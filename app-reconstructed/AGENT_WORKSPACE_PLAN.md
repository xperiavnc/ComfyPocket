# Agent 项目与会话管理方案

- 状态：待实施；本次仅修订方案，P1–P4 均未开始
- 编写日期：2026-10-20
- 修订日期：2026-10-20
- 工程：`app-reconstructed`
- 范围：Agent 页面布局、项目与会话管理；不改主底栏的样式、位置或切换行为
- 设计参考：`agent-page-ui-v4.html`、`agent-projects-layout-v2.html`、`agent-sessions-delete.html`（本地 UI 方案稿）
- 功能边界、数据规则和验收以本修订为准；设计稿只作视觉参考，不代表页面已经实现

## 1. 目标

把 Agent 从单一、持续增长的聊天页，改为由项目和独立会话组成的工作区。用户可以创建项目、在项目中管理多段对话、快速恢复最近会话；会话长按后可删除。当前绘图和 Chat 能力、工作流选择、提示词展示、生成媒体预览及 Agent 设置继续保留。

项目承担长期资料，会话承担一段独立任务的消息、附件、草稿、工作流配置和生成记录。项目功能是本次范围的一部分，不是可选项。同项目的会话默认互不读取聊天内容。

实施前先落实四条约束：

1. AI 回复与服务器出图任务是不同生命周期；切换会话不改变已提交任务的归属。
2. 清理一段会话只处理该会话的文件引用，不清空共享附件目录。
3. 迁移检查所有可恢复数据，不以聊天消息是否为空作为唯一条件。
4. 恢复会话同时恢复其工作流参数和提示词状态，不只恢复模板引用。

## 2. 当前工程基线

- Agent 主页面在 `app/src/main/java/com/comfyui/mobile/ui/screens/AgentScreen.kt`，聊天列表和输入区在 `ui/screens/agent/AgentChatPanel.kt`。
- `AgentChatMessage` 已包含消息正文、附件、澄清问题、正反向提示词及角色选择等信息，可沿用作会话消息的数据载体。
- `MainViewModelAgent` 用按运行环境命名空间隔离的 SharedPreferences JSON 保存一份消息列表，最近媒体、正反提示词、任务 ID 另行保存；还没有项目或会话实体。
- `AgentSessionController` 只管理单轮 AI 请求身份。现有停止逻辑已提示服务端接收的任务可能继续运行；本地媒体事件和云端 Agent 输出仍更新一份 Agent 结果列表。
- 已有 `TaskStore/TaskRecord` 保存服务器和远程任务身份，尚无会话归属。新方案复用现有任务查询、费用和输出逻辑，不另造重复的任务引擎。
- 当前工作流参数按作用域和模板保存；输入框、滚动位置和待发附件也没有会话隔离。
- 当前清空聊天会遍历 `agent_attachments` 目录删除文件；多会话实施时需替换这条清理路径。
- 当前备份主要覆盖配置、工作流、应用和任务；新会话数据与附件的备份规则需在 P1 同步补齐。
- 工程已有 `LocalFloatingNavClearance`。新页面和底部操作区继续使用此间距，不得遮挡悬浮底栏或输入区。
- 当前未配置 Room。Room、schema 和配套代码生成的构建接入属于 P1 实施工作，本次文档修订未引入依赖。

## 3. 归属与作用域

### 3.1 运行环境与执行服务器分离

- `scope` 延续 `local` / `cloud@<siteId>`，项目和会话不得跨作用域静默移动。
- 为兼容现状，本地服务器之间继续共享 `local` 会话空间，不在本次自动拆分历史。共享会话空间不等于共享任务来源。
- 每次绘图都捕获独立的 `executionTarget`：后端类型、稳定服务器配置 ID、云端站点和必要的非敏感来源标识。回调按原目标归档，不读取当前连接来推断来源。
- 云端沿用现有账号和站点匹配校验；账号或配置缺失时保留历史，显示需重新绑定，不把任务改投其他账号。
- 会话保存上次选择的目标引用；打开会话不自动修改全局服务器连接。当前连接与会话目标不一致时，提交前让用户确认目标；离线浏览不受影响。
- 旧数据缺少来源时标记为“来源待确认”，可用本地文件继续展示，不根据迁移时的当前服务器猜测来源。
- 媒体身份包含来源与远程路径，或应用管理的本地资产 ID；只用文件名、子目录和类型不足以区分不同服务器的同名文件。

### 3.2 设置分层

| 层级 | 内容 | 修改影响 |
| --- | --- | --- |
| 全局/作用域 | LLM 配置档案、角色与服装词库、绘图规则、画风辅助设置、模板默认绑定 | 继续保留现有设置入口；是新会话的默认来源 |
| 项目 | 名称、说明、可选指令、参考资料、默认工作流引用 | 默认值只影响之后创建的会话；已有会话不被静默覆盖 |
| 会话 | 模式、选用的 LLM/目标引用、工作流配置、提示词、消息、草稿和媒体关联 | 仅影响当前会话 |
| 单轮/任务 | 请求身份、捕获的配置、实际提交参数、服务器和远程任务身份 | 创建后固定，不随页面切换重新解释 |

- 新会话的工作流默认值顺序：用户显式选择 > 项目默认值 > 当前作用域默认值。
- 会话内切换模式、LLM、服务器或工作流是显式操作，不反向改写其他会话和全局默认值。
- 配置档案被删除时保留名称/引用提示，要求重新选择；阅读历史不触发重新请求或自动出图。
- API Key、认证头和服务器凭据继续由现有凭据存储管理，不复制进项目、消息或执行快照。

## 4. 页面结构

### 4.1 Agent 对话页

- 顶栏继续显示 Agent 标题、当前工作流/角色配置入口及设置入口。
- 增加紧凑的“项目名 / 会话名”入口；未归入项目时显示“未归入项目”。长标题截断，不挤压主要控制项。
- 保留 Chat/绘图模式、模型配置、最近生成入口、聊天和输入区；最近生成只显示当前会话的关联结果。
- 底栏维持现有实现，不调整图标、选中态、布局、动画或路由。
- 首版锁定为 Agent 内的全屏子页面承载工作区，不同时实现抽屉；沿用现有子页进入/返回效果，不改变主页面切换动画。
- 不在聊天内容区域常驻大块项目面板。

### 4.2 项目与会话工作区

- 顶部提供搜索，以及“新建项目”和“新建会话”入口。
- 首版搜索项目名/说明、会话标题/摘要；界面标明搜索范围，不承诺消息全文检索。
- 项目项显示名称、说明摘要、会话数量和最近更新时间；提供浏览、编辑、归档及归档入口内的恢复操作。首版项目移除操作限于归档，不含彻底删除。
- “最近会话”区域按更新时间倒序展示最近对话，标明所属项目或“未归入项目”、时间及简短消息预览。
- 浏览项目只改变工作区的浏览位置，不替换当前正在聊天的会话，也不触发 AI 停止或出图。
- 项目详情显示说明、指令/参考资料入口、会话列表和新建会话入口。只有点按会话或确认新建会话才切换聊天上下文。
- 项目列表与最近会话共用工作区；空项目、无会话、搜索无结果均有直接创建入口。
- 阅读会话不刷新活动时间；消息新增、重命名和配置变更才更新相关活动信息。流式输出不逐字重排最近会话列表。

### 4.3 会话、归档与返回

- 新建会话默认归属正在浏览的未归档项目；从顶层新建时可选项目或“未归入项目”。空白新会话预留稳定 ID，首次显式修改配置、保存非空草稿/附件或发送消息时才持久化，避免大量空壳记录。
- 点按会话先保存原会话状态，按第 6 节完成运行身份切换，再恢复新会话；列表加载期间不显示上一会话的残留内容。
- 恢复内容包括消息、澄清问题、模式、工作流配置、正反提示词、草稿、待发附件、滚动锚点和会话生成记录。
- 长按会话进入单项选中态，提供删除；更多菜单提供重命名、移动和删除等价入口，不把长按作为唯一操作方式。
- 删除前二次确认，展示会话标题、聊天附件影响和未完成任务数量；明确删除记录不等于取消服务器任务。
- 删除当前会话后，恢复同作用域内最近的未删除、非归档会话；没有其他会话时显示“未归入项目”的空白新会话状态。
- 移动会话只改变同作用域内的项目关联，不改变会话 ID、消息或任务归属；提供撤销入口。
- 归档只改变项目的可见分组，不删除会话、不取消任务；普通项目/最近列表默认过滤已归档项目，归档入口仍可查看和恢复。
- 归档当前项目不强制关闭当前会话，当前页显示归档状态；归档项目新建会话前先恢复，已有会话可继续使用且不会自动解除归档。
- 系统返回优先遵循现有输入法/前景弹层处理，再退出选择态、项目详情、工作区并回到 Agent。一次返回事件只消费一次，不同时触发主页面退出。

## 5. 数据模型与持久化

### 5.1 实体职责

| 实体 | 核心字段 | 说明 |
| --- | --- | --- |
| `AgentProject` | `id`、`scope`、`name`、`description`、`instructions`、`defaultWorkflowRef?`、时间戳、`archivedAt?` | 首版名称必填；不实现项目彻底删除 |
| `AgentConversation` | `id`、`scope`、`projectId?`、`title`、`mode`、`llmProfileId?`、`executionTargetRef?`、`workflowRef?`、时间戳、`lastMessagePreview` | 会话索引，不在列表查询中加载全部消息和配置 |
| `AgentConversationState` | `conversationId`、`workflowStateJson`、`promptOutputJson`、`draftJson`、`scrollAnchorJson`、`schemaVersion` | 会话级配置与 UI 可恢复状态；JSON 内引用资产 ID，不重复保存文件 |
| `AgentMessage` | `id`、`conversationId`、`sequence`、`payloadJson`、`payloadVersion`、`createdAt` | 沿用 `AgentChatMessage`；兼容旧字段，保留正反提示词和澄清信息 |
| `AgentExecutionLink` | `id`、`turnId`、`conversationId?`、`scope`、`executionTarget`、`taskLocalId?`、`remoteId?`、`submissionState`、`snapshotJson`、时间戳、`detachedAt?` | 仅负责提交身份、运行快照及会话归属；不复制任务引擎的费用、轮询和完整状态 |
| `AgentConversationMedia` | `conversationId`、`mediaKey`、`sourceDescriptor`、`executionId?`、`createdAt` | 保存可解析的来源描述及关联，不只有一个缺少目标记录的字符串 |
| `AgentAsset` | `id`、应用内相对路径、文件名、类型、大小、校验值、时间戳 | 应用管理的聊天附件和项目资料，不接管用户媒体库原文件 |
| `AgentAssetRef` | `assetId`、`ownerType`、`ownerId`、用途 | 引用归项目、消息或会话草稿；事务内检查所有者有效及唯一关系 |
| `AgentMigrationState` | 迁移版本、`scope`、来源指纹、目标会话 ID、校验结果、完成时间 | 作为迁移完成的数据库内权威标记 |

### 5.2 工作流恢复契约

- `workflowRef` 记录模板来源、稳定标识和可用的版本/指纹；模板本身仍是共享资源。
- `workflowStateJson` 保存会话参数覆盖、正反向节点绑定、辅助节点选择及恢复所需的配置，不把会话参数写回模板默认值。
- `promptOutputJson` 保存最近正向、反向及其状态，供该会话后续请求使用；不读取另一会话的“上一次提示词”。
- 每轮提交前捕获实际配置快照；项目默认值、模板或其他会话之后的修改不改变已提交任务的解释。
- 模板被更新或移除时对照版本检查字段；缺失节点要求重新绑定，不静默替换模型或改投当前模板。

### 5.3 存储边界

- 使用 Room 保存上述数据；引入代码生成配置并导出 schema，升级以显式迁移保留用户数据。
- Repository/Store 提供 `StateFlow`，Compose 不直接访问数据库、SharedPreferences 或附件文件。
- 项目与会话须同作用域；消息顺序在会话内唯一；执行和媒体去重键包含来源，收到重复回调不重复入库。
- 会话消息分批读取；流式响应合并/节流更新单条消息，终态落盘，不逐 token 序列化整段历史。
- 数据库操作放 IO dispatcher；新增消息、配置变更、删除关联和迁移使用明确事务。
- Room 与现有 JSON `TaskStore` 不具备跨存储事务：执行归属以 Room 记录为准，任务镜像通过稳定 ID 幂等补齐，启动时校对未完成关联。
- 全局角色档案和模板默认设置留在原作用域存储；完成迁移后新会话记录只写新存储，不并行维护两份可分歧的聊天真相。

## 6. 请求、服务器任务与会话切换

### 6.1 AI 请求生命周期

- 发送时捕获不可变的 `conversationId`、`scope`、turn ID 和配置，消息写入显式指定会话。
- 首版仍保持一个前台 AI 请求，不增加多会话并行 AI 回复。切换时先使原运行身份失效，取消原 AI 网络请求和本地续执行，再切换展示。
- `AgentSessionController` 保留 turn identity 校验，并加入会话和作用域校验；旧响应不修改新会话，也不继续打补丁或提交出图。
- 同一会话修改执行目标或工作流时也推进配置版本并使旧请求失效，不把旧回复应用到新配置。
- 保存已收到的部分回复并标记停止；应用进程中断后将未完成回复标记中断，不自动重发用户任务。
- “停止回复”“取消尚未提交的绘图”和“取消已提交的服务器任务”明确区分；现有停止按钮不冒充服务器取消成功。

### 6.2 服务器任务生命周期

- 网络提交前先持久化 `AgentExecutionLink` 及目标/配置；服务器确认后记录远程 ID，并关联现有任务记录。
- 服务器已接收的任务独立继续运行。切换会话只改变前台展示，结果按执行关联写回原会话；重启后仍按同一来源恢复跟踪。
- 提交请求中断但是否接收不明确时标记“提交状态待确认”；只做现有服务支持的核对，不自动重试生成，避免重复任务和重复计费。
- 本地 WebSocket、历史补查及云端轮询都先通过持久化关联确定会话，不向当前会话或当前作用域兜底追加结果。
- 重复回调、补查和轮询幂等合并；一个任务产生多张图片/视频时保留完整结果集合。
- 旧任务缺少可靠来源或归属时进入待确认历史记录，不绑定到切换后的会话。
- 删除会话时取消尚未提交的本地续执行，解除执行关联的会话引用并标记 `detachedAt`，保留已有任务身份。后续结果按现有任务/媒体保存策略处理，不重建被删会话。
- 用户显式请求取消服务器任务时，复用后端现有取消能力并记录实际结果；取消失败或结果未知不等于任务已结束。

### 6.3 草稿与异步界面状态

- 输入草稿、光标/选择、待发附件、滚动锚点和当前澄清问题都按会话恢复，不复用一份页面级状态。
- 文件/图片选择器在打开时记录发起会话；导入任务携带该 ID，切换后仍归原会话。原会话已删除时丢弃导入并清理临时引用，不转入当前会话。
- 配置页、模型选择器和异步工作流加载同样携带发起会话/版本；过期结果不覆盖新会话配置。
- 澄清选择只影响所属会话，恢复后保留原始请求；已回答的旧问题不再次提交或触发出图。

## 7. 附件与文件清理

- 新文件保存到应用管理目录，以资产 ID 和相对路径引用；同安装内的旧绝对 URI 经校验后转换为资产引用。
- 聊天消息、草稿和项目资料分别建立引用，文件可共享但所有者明确；存在引用的文件不被其他会话清理。
- 删除会话在事务中删除消息/草稿引用和会话媒体关联、解除执行归属；仅将无任何引用的应用管理资产加入清理队列。
- 实际文件删除在事务提交后执行并可重试；重新检查引用，避免清理与导入/共享并发造成误删。
- 清理只操作应用管理的附件路径，不删除用户媒体库、下载目录、外部源文件或服务器模型/图片。
- 停止使用清空整个 `agent_attachments` 目录的旧路径。切换会话、切换服务器和归档项目均不清理附件。
- 缺失或损坏的旧附件保留名称及缺失状态，不伪造恢复成功，也不因此丢弃整段会话。
- 首版沿用现有图片/文本文件大小及数量限制，不新增任意文档解析或远程资料抓取。

## 8. 旧数据迁移

### 8.1 迁移清单与空聊天

- 按实际存在的键枚举作用域，检测 `agent_messages__<scope>`、`agent_latest_media_list__<scope>`、`agent_prompt_output__<scope>`、`agent_last_prompt__<scope>`、`agent_run_prompt_ids__<scope>`、当前模板/参数及其附件。
- 兼容现有读取中的旧版无作用域键；每组旧数据只归入一个有记录的迁移目标，优先明确来源，否则归入 `local` 的“来源待确认”记录，不向所有作用域复制。
- 聊天非空时创建“历史会话”，`projectId = null`，保留消息 ID、顺序、时间、附件、正反提示词、澄清和角色选择信息。
- 聊天为空但有媒体、有效提示词、任务 ID 或可恢复会话配置时，创建明确标记的“历史生成记录”会话；纯默认设置不构成历史会话。
- 仅有未关联的旧文件时保留并列入待确认资产清单，不猜测所属消息、不直接删除；完全没有可恢复记录时不创建空壳项目/会话。
- 旧模板参数只初始化迁移会话自身配置，之后与模板默认值及其他会话独立。

### 8.2 原子性、重试与降级

- 迁移期间短暂关闭该作用域的新写入入口，读取一致的旧数据快照，避免消息或附件在复制中被修改。
- 每个作用域使用固定迁移目标和稳定记录映射；同一迁移版本重复启动不重复建会话、消息或任务关联。
- 必要文件先暂存并校验；数据库行、引用和 `AgentMigrationState` 完成标记在同一事务提交。SharedPreferences 标记仅作兼容信息，不单独决定完成。
- 校验消息数、媒体数、提示词、已知任务映射、附件数量/可读性及关键字段；缺失文件和未知来源独立记录，保留原始数据。
- 失败时回滚该次数据库事务、保留旧键和原文件，继续旧模式并提供重试；重试前重新获取旧模式的最新快照。
- 成功后新存储为唯一写入源。旧键和文件在首版保留为只读迁移快照；降级旧 APK 不会自动获得新会话，旧快照仅覆盖迁移前数据，不作为完整的新数据回退。
- 迁移错误日志仅记录计数、状态和脱敏身份，不记录密钥或整段私人对话。

## 9. 项目指令与参考资料

- 项目说明默认只用于工作区展示；项目指令单独启用，参考资料按用户选择作为上下文，不把所有附件自动附加到每次请求。
- 项目资料引用 `AgentAsset`，保存用途、显示名、版本和启用状态；首版支持现有文本/图片附件类型，不引入资料检索引擎。
- Chat 与绘图都使用同一上下文组装入口，按稳定顺序组织：现有全局人设/绘图规则、项目补充指令、选中参考资料、当前会话历史、当前用户请求。
- 项目指令补充偏好，不覆盖全局配置；用户显式选择优先于项目默认值。角色/服装匹配、澄清和正反向提示词约束继续沿用现有策略。
- 参考资料和词库内容作为带来源的数据，不提升为系统指令；不同会话的消息不自动进入项目上下文。
- 沿用现有上下文/输出长度设置，将项目资料一并计入预算。优先保留当前请求和本轮已确认的角色/服装约束，按规则裁剪较旧历史及低优先级资料，并反馈被省略的来源。
- 必需输入自身超预算时提示用户减少资料或调整长度，不静默截断关键触发词，也不凭空扩大模型上下文。
- 每轮捕获使用的项目指令/资料版本；请求进行中编辑项目不重写已捕获配置。项目改名、资料更新不修改历史消息。

## 10. 备份与恢复契约

- 备份格式、导出和恢复逻辑在 P1 一起接入，不等 P4 才处理；P4 做入口整合和完整回归。
- 沿用 `.cui.bak` 容器并增加可识别的工作区数据版本/清单，保持旧备份可导入；未知新版本先提示版本不支持，不覆盖现有数据。
- 工作区导出包含项目、会话、消息、配置/草稿、媒体来源、执行归属及被引用的附件；资产用包内相对路径、大小和校验值描述，不导出原设备绝对 URI。
- 复用现有任务记录导出能力；即使用户不导出完整任务历史，也保留会话媒体所需的最小执行/来源信息。
- 执行记录和附件引用使用一致快照；文件在打包期间保持被引用或受临时保留保护，避免备份中途被清理。
- 密钥仍服从现有备份选项，不因新增执行快照绕过“是否包含密钥”的选择。
- 首版恢复采用明确确认后的工作区替换，不做隐式合并；先校验并在暂存区重建引用，保留可回滚的原工作区后再切换。
- 恢复前停止前台 AI 和本地续执行，推进工作区版本并暂停写入；旧版本的异步回调不写入恢复后的工作区。已提交服务器任务仍按第 6 节独立处理。
- 无工作区段的旧备份不清空现有工作区。缺失 LLM、服务器或模板引用显示待重新绑定，不自动改指向。
- 恢复时重建本地资产路径、检查唯一 ID、作用域和外键；中断的 AI 回复标记中断，任务先核对身份，不重发出图。

## 11. 分阶段实施

每阶段完成后分别验证、提交并推送；只有文档修订不代表任一功能阶段完成。

### P1：存储与迁移

- 接入 Room/schema、DAO、Repository，建立会话状态、资产引用、执行归属和迁移元数据。
- 实现一致快照迁移、空聊天历史保留、旧版键兼容、幂等重试及旧模式降级。
- 改造任务与媒体入口以显式携带会话/来源；替换全目录附件清理，落地配置快照。
- 同步实现工作区备份/恢复格式、相对路径重建及无工作区段的旧备份兼容。
- 先接入单一会话读写；仓储层用多个会话验证隔离，现有 Agent 页面功能保持可用。
- 阶段出口：迁移、归属、文件清理和备份用例通过，现有 Agent 回归及 Debug 构建通过；涉及数据库的集成用例与纯 JVM 测试分别报告。

### P2：会话管理

- 接入最小可用会话工作区，增加新建、命名、恢复、搜索、最近排序、长按和更多菜单。
- 实现删除确认、同作用域恢复策略、空白状态以及草稿/附件/滚动状态恢复。
- 所有异步选择器、模板加载、澄清和请求切换绑定原会话。
- 阶段出口：会话 A/B 不串消息、参数或媒体，生成中切换与删除、重启恢复均有通过记录。

### P3：项目管理

- 增加创建、编辑、浏览、归档和恢复项目；不实现项目彻底删除。
- 增加项目内新建/移动会话、撤销及“未归入项目”列表，浏览项目与进入会话分离。
- 接入项目说明、默认值、可选指令及参考资料；按第 9 节组装和裁剪上下文。
- 阶段出口：项目默认值不覆盖已有会话，归档不丢记录；上下文顺序、预算和会话间资料隔离测试通过。

### P4：页面整合与完整验收

- 整理全屏工作区与 Agent 页面密度、标题层级、空状态和现有进入/返回效果。
- 验证小屏、长标题、键盘、附件、悬浮底栏安全间距及单次返回消费。
- 整合备份选项/提示，执行完整迁移、升级、导出恢复及现有功能回归，不把备份底层接入推迟到此阶段。
- 按“软件名＋版本号”导出 APK，报告实际测试范围、构建结果和 GitHub 备份结果。

## 12. 验收矩阵

以下为待执行标准，不是本次文档修订已通过的功能测试。

| 场景 | 预期结果 | 最早验证阶段 |
| --- | --- | --- |
| 旧聊天及正反提示词完整 | 顺序、字段、澄清和角色选择保留 | P1 |
| 旧聊天为空但有生成媒体/任务 ID | 进入历史生成记录，不因消息为空丢弃 | P1 |
| 迁移中断、文件缺失、再次启动 | 原数据保留、缺失可见，重试不重复导入 | P1 |
| 旧版无作用域键、来源不明 | 只迁移一次，未知来源不绑定当前服务器 | P1 |
| A/B 共用工作流，各改模型/尺寸/绑定 | 会话配置及最近正反提示词独立 | P1/P2 |
| A 提交出图后切到 B | A 的图片/视频仍归 A；B 不被追加结果 | P1/P2 |
| 提交确认丢失或重复媒体回调 | 不自动重复生成，关联/结果幂等 | P1 |
| 两台本地服务器产生同名文件 | 来源与媒体键区分，下载不指向当前连接兜底 | P1 |
| 删除 A，B 与项目资料引用同一资产 | 只清 A 的引用，B 和资料文件保留 | P1/P2 |
| 删除 A 后服务器任务完成 | 不重建 A，不误写 B，保留常规任务身份 | P1/P2 |
| 在 A 打开选择器/加载模板，切 B 后返回 | 只更新 A；A 已删除时清理临时导入 | P2 |
| 草稿、附件、澄清、长列表切换/重启 | 恢复所属会话状态，不重复提交问题或任务 | P2 |
| 浏览项目但未选择会话 | 当前聊天和运行身份不改变 | P3 |
| 项目指令、资料、角色/服装与长度预算 | 顺序明确、来源可识别，不读取兄弟会话 | P3 |

| 新备份恢复、旧备份无工作区段 | 路径重建、引用一致；旧备份不清现有聊天 | P1/P4 |

| 小屏、长标题、两种底栏和页面动画 | 内容不被挡，主底栏和切换效果保持原样 | P4 |
| Agent 原有 Chat、绘图、词库复制等 | 正反提示词、角色/服装澄清、附件和预览无回归 | 每阶段 |

## 13. 暂不纳入

- 项目协作、云端同步、多设备冲突合并。
- 项目成员/权限系统、项目分享。
- 自动将所有历史聊天智能归类到项目。
- 多会话同时运行 AI 请求、消息全文检索、参考资料检索引擎。
- 项目彻底删除及跨作用域移动；不同本地服务器历史自动拆分。
- 删除会话时清理服务器或媒体库原始文件。
- 重做应用底栏或改变 Agent 与其他主页面之间的切换动画。
