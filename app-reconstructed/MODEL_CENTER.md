# 模型中心 · P0–P1

本批是模型资料管理阶段，不等于 Agent 接线首版全部完成。
P2 图编辑引擎、P3 Agent 工具与角色词库写入、P4 组合交付仍单独实施。
不改变已有角色库、正反向提示词、自定义系统人设或当前工作流。

## 入口与操作

- 主页原“资产”区的 **本地模型 / 数量** 整块进入本地页。
- 同一位置的 **集市 ↗** 进入在线页；**插件 / 数量** 进入原已装插件列表。
- 模型中心仅有 **本地模型 / 在线集市 / 下载任务**，不增加主页卡片或第六底栏。
- 两种底栏、根页面切换、二级页返回、弹窗 portal 沿用现有实现。
  本地详情复用同套 280 ms 进入 / 220 ms 退出淡化，详情返回先到列表。
- 首次本地页请求触发电脑后台扫描；先显示清单，再分块计算 SHA-256。
  “同步 / 暂停同步”控制本地索引任务，不提交生成或下载权重。
- 搜索名称、中英文别名、角色 / 作品、服装、标签、备注和已确认触发词。
  目录、注册类型、多用途、底模、收藏、来源 / 完整度、排序独立保存。
  大小、修改时间降序；最近使用没有记录时为未知，不冒充修改时间。
- 卡片 / 紧凑视图、筛选和滚动按服务器配置 ID + 服务地址分区。
  当前手机缓存仅包含浏览 / 详情读取过的条目，不宣称已缓存整台电脑。
  离线搜索只查询这些缓存，显示缓存时间，不把缓存当文件仍存在的证明。
- 详情可编辑别名、用途多标签、角色 / 作品、服装、底模覆盖、原拼写触发词、
  收藏、常用权重、备注及分类锁定；使用修订检查防止迟到保存覆盖新标注。
  可以撤销上次标注，撤销也创建一个新的修订。
- “补全资料 / 刷新来源资料”和“本页补全”进入独立轻量队列；
  任务页仍复用原生模型权重下载队列。保存成功后才显示已保存。
  打开页面不会自动联网识别；已有资料默认复用，刷新需显式选择。

## 电脑端安装

需要配套 **ComfyUI-Mobile-Bridge 2.2.1**，本地封面读取需同步更新插件：

1. 停止 ComfyUI，备份原插件目录；不要把备份副本留作同时启用的第二个插件。
2. 替换 `custom_nodes/ComfyUI-Mobile-Bridge/` 的完整代码目录。
   `model_center.py`、`model_index.py`、原有配套模块和 `web/` 都要保留。
3. 保留 ComfyUI **用户目录**下的 `mobile_bridge/`。它不是插件源码的一部分，
   保存电脑 Key、下载任务和模型资料。升级目录不应删除或覆盖它。
4. 重启 ComfyUI，手机重新连接，在本地页同步。
   旧插件会显示明确的能力缺失提示，在线市场的手机直连模式仍可独立使用。

本批没有自动安装、替换远端插件、重启 ComfyUI、卸载手机应用或提交生图。
电脑实际部署后的用户目录路径以该实例 `folder_paths.get_user_directory()` 为准。

## 数据与身份

```
<ComfyUI user directory>/mobile_bridge/
  civitai-settings.json       # 原有电脑凭据
  download-tasks.json         # 原有模型下载队列
  model-center/
    index.sqlite
    metadata/<sha256>/provider.json
    previews/<sha256>/<image-url-hash>.image
```

- 新依赖只有 Python 标准库中的 SQLite / 线程机制；网络复用 ComfyUI 已有 aiohttp。
- `schemaVersion=1`；资料库持久化独立 `serverId`。根目录 ID 来自注册分类及规范化路径，
  位置 ID 来自根目录、分类和相对路径；位置的完整身份还包含该服务器 ID。
- 注册类别是 LoRA / checkpoint / UNet / VAE / 文本编码器。
  GGUF 仅是文件格式，不从扩展名猜用途或底模。
- 扫描所有对应注册根目录，保留同名的多个位置。统计分别显示位置数、物理路径字节数、
  已哈希位置数和已知唯一内容数，未完成枚举 / 哈希不假装是完整库。
- 节点名称只使用注册分类 API 的精确选项和 `get_full_path` 的实际解析；
  不靠 basename / 后缀拼接。多根同名标记有歧义，返回空 `nodeModelName`。
  P2 接线时仍须核对当时目标节点的实际 `/object_info`；本批不宣称实际加载成功。
- 大目录扫描和文件哈希在工作线程运行，网络队列低并发；列表无需等哈希完成。
  每 1 MiB 检查停止标记，哈希前后比较 size / mtime / inode，变化结果不发布。
  暂停 / 取消会等待读取线程结束，保留已完成资料；继续增量扫描。
  不可读目录标为未确认，不把读取失败误作所有文件被删除。
- 文件移动 / 改名后重算指纹关联同内容资料；消失的位置保留。
  同 SHA 共用提供方资料；哈希前各位置已有相互冲突的人工记录时保留位置覆盖，
  不静默丢弃任意一份标注。内容更换后不沿用旧内容的哈希和提供方身份。
- 人工标注独立于 provider JSON，刷新来源不覆盖人工内容，保留历史修订。
  未分类、人工确认和 AI 建议状态有独立字段；本批不自动生成分类建议。

## v1 API 契约

所有 JSON 路由使用 `{code, msg, data}` envelope，成功 `code=0`；
非成功使用对应 HTTP 状态。预览为独立图片响应。

前缀：`/api/mobile/model-center`

| 方法 / 路径 | 数据 / 行为 |
| --- | --- |
| `GET /capabilities` | schemaVersion、serverId、能力、注册目录、扫描状态、上次同步 |
| `GET /models` | `q,category,rootId,useCase,baseModel,source,favorite,sort,page,pageSize` |
| `GET /models/{id}` | 文件位置、指纹、节点名称状态、provider、annotation、revision |
| `POST /models/{id}/annotation` | `{expectedRevision,annotation}`；撤销附加 `undoRevision` |
| `POST /scan` | `{action:"start"|"pause"|"resume"|"cancel"}` |
| `POST /enrichment` | `{locationIds:[...],refresh:false}`；每次 1–100 项 |
| `GET /tasks` | `{scan,enrichment}`；不混入大模型权重下载计数 |
| `POST /task-action` | `{id,action:"pause"|"resume"|"cancel"}` |
| `GET /installation` | `modelId,versionId,fileId`；哈希关联文件 / 其他版本 / 未确认 |
| `GET /models/{id}/preview?index=0&v=…` | 优先同目录 JPEG / PNG / WebP 封面，否则按需下载并独立缓存来源图片 |

`pageSize=1..100`，默认 40；分页和排序在电脑进行，只返回所需候选页。
UI 与后续 Agent 适配层复用 `LocalModelQuery`，不把整库灌入模型上下文。
资料更新需要精确位置 ID 和 expectedRevision；冲突返回 409。
接口没有删除、移动模型文件、改图、写个人词库或 `/prompt` 动作。

用途键：`character/style/clothing/pose/scene/lighting/other`，允许多选；
`unclassified` 为列表查询条件，不是推测出的用途。
人工标注字段见 `ModelAnnotation`，分类来源 `user/ai-suggestion` 与
状态 `confirmed/suggested/unclassified` 分开，不将 AI 建议当身份事实。

## Civitai 与下载联动

- 电脑使用现有服务端 Key / HTTP 代理调用 `model-versions/by-hash/{完整SHA256}`。
  手机的 Key / 代理不自动复制到电脑；这里只上传指纹，不上传模型权重。
- 校验返回版本 `files[]` 中实际匹配 SHA-256 的文件，不盲选 primary。
  缺失作者、版本描述或触发词时保持未知，不编造身份或“无需触发词”。
- 404 未匹配有 24 小时冷却；其他失败默认 5 分钟，429 采用服务端 Retry-After
  并对后续资料任务退避；超时单独标为 408。均保留已有资料和人工标注。
  重复任务去重，任务恢复保持显式刷新意图，电脑重启后未结束资料任务暂停。
- 提供方简介只渲染为普通文字，不作为 Agent 指令；可见卡片和详情按需自动请求封面。
  图片网络 / 格式失败不回滚文字资料；模型触发词保留原大小写和特殊拼写。
- 原生模型下载长度与 SHA-256 校验通过、发布文件后，再通知模型中心入库并保存
  此次已获取的版本资料，不重哈希整文件。索引 / 资料失败只报告“模型已下载，资料待补全”，
  不把权重标为失败或重新下载。
- 在线详情中的安装状态使用当前电脑、已核验内容的 provider model/version/file ID，
  且复核文件 size/mtime；同名文件不是安装依据。未索引不代表一定未安装。

代码中含注册目录、重复位置、精确匹配、增量失效、保存修订 / 撤销、重启、

并沿用原集市返回、正反提示词、画廊和设置回归。

2026-10-18 的 P0–P1 初次勘验仅对用户指定的 ComfyUI 进行 GET：两种标准 LoRA 节点存在，
当时 Bridge 为 2.1.0，模型中心 capability 路由为 404。这是历史记录，不代表后续部署状态；
用户模型名、目录、设备信息和接口原始返回只留本地，不进入此文档或 Git。

不是用户浏览器当前画布，也未向真实服务器 POST `/prompt`。

因此自动化验证不代表手机真机帧率、远端新插件部署、真实受限模型的 Civitai 账号
匹配或 Agent 实际接线已通过；这些需要相应后续阶段 / 部署联调。
