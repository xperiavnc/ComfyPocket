## 0.0.40 角色绘画词库消歧

- 角色名和别名只用于识别用户对话，不作为绘画 tag。服装触发词命中后由 App 选定预设，只向模型提供该预设的绘画标签。
- 有多套服装可选、命中重名角色或重名服装触发词时，在 Agent 回复中显示可点选项；等待选择期间不改工作流、不提交出图，也不调用模型猜选。
- 用户选择某个服装后，继续按该预设 ID 路由；选择“自定义服装”进入自定义分支，不再次回到服装选项。明确指定两个互斥预设，或有多套服装但没有设置默认时，同样先选择。
- 已选服装预设或本轮自定义服装时，默认不混入词库中的其它版本；明确要求查询词库角色版本时，则按名称和别名单独检索，暂停未匹配的默认服装。
- App 直接处理本地词库版本消歧，不依赖模型猜选。多版本先选版本，有可选外貌时再单独询问；原始画面要求随确认流程保留。确认前不调用模型、不改工作流、不提交出图。
- 确认后仅把选中的词库角色行交给模型，补齐选定的身份标签；拒选可选外貌时移除这些候选字段，只有明确选择加入后才补入相应可选标签。未登记角色档案的词库角色也支持同一流程。
- 模型返回结构化澄清问题时，聊天中同样显示选择项；即使响应误带 `should_draw=true`，也跳过工作流执行，且不恢复旧画面提示词。
- “绘图时始终启用”从角色档案编辑页移至 **Agent → 画风与辅助参数**，在那里即时保存；角色档案页仅编辑角色内容及服装预设。
- 本地 debug APK 构建和 759 项 JVM / Compose / ViewModel 集成测试通过；包含两步词库确认、选项续接、可选外貌同意 / 拒选、确认前零提交、角色常驻保存，以及深色 / 窄屏长标签换行。验证不等同于真实模型服务或手机端到端测试。

## 0.0.39 角色识别词与绘画标签分离

- 角色名称 / 别名是 App 用于匹配用户对话的识别词，不作为绘画标签输入；发给模型的档案只包含本轮 App 已确认的角色，不传递整个角色目录，也不让模型挑角色。服装名称和服装对话触发词不发给模型，只给已选预设的绘画标签。
- 角色编辑页将“AI 对话识别名称 / 别名”与“角色绘画外貌参考 / 固定绘画标签”分别标注。服装编辑拆成“AI 对话触发词”和“本套服装的绘画标签”。
- 每套服装可登记多条对话短语，例如“换成日常穿搭”“穿轻便衣服”。本轮用户消息命中后，App 在唯一模型请求之前确定该服装 ID，把已选预设的绘画标签给模型；模型不需自行选择预设。默认服装回退收进可选展开项，不再把每张预设卡显示成需要手选的单选项。
- 未填写服装对话触发词时，为兼容旧档案仍以预设名称匹配。触发词同时命中多套服装时提示配置冲突，本轮不调用模型或提交工作流。
- 输出应用前从正向和反向提示词中剔除作为独立项出现的角色名称 / 别名、服装名称 / 对话触发词，以及去掉“换成 / 穿上”等前缀后的服装识别短语。明确填在绘画字段中的同名标签优先保留，不做任意子串删除；未发生过滤时保留原文格式。
- Gson 旧 JSON / 备份中的服装未含对话触发词时继续读取；没有额外网络或模型请求。只筛选逗号 / 换行分隔的独立项，不对自然语言句子子串做删改。
- 本地 Android debug 构建与 741 项单元 / Compose / ViewModel 集成测试通过；包含对话服装自动路由、预设触发词重名阻断、正反向识别词清理、绘画字段同名保留、旧 JSON 兼容与窄屏编辑。

## 0.0.38 角色识别与服装触发词

入口：**Agent → 画风与辅助参数 → 管理词库**。长按角色胶囊也进入同一编辑页。

### 不依赖模型“记得调用”

角色匹配在发出本轮唯一的模型请求之前由 App 完成，随后直接提供结构化档案，
不新增 tool calling 协议、不额外请求一次 AI、不依赖 AI 猜出库里登记的角色。

- 每个角色可以登记多个中文 / 英文别名、昵称；英文大小写及下划线 / 空格兼容，
  不进行模糊拼写、翻译或作品身份猜测。英文短名不命中更长姓名中的子串。
  完整长名优先于其内部短名，同位置的登记全名优先于另一角色的别名。
- 同一个别名指向多个角色时，给出重名反馈，本轮不调用模型或提交工作流；
  使用登记全名或改为唯一别名即可。不会默认挑第一项，也不会把两个角色混成一个。
- 已启用只表示允许匹配；“绘图时始终启用”才是常驻。停用、明确排除该角色或
  “本次不用角色库”均不注入；常驻不是让模型每次自行挑一个角色。
- “保持人物，换背景”“她换便服”等续改按上一条成功生成提示词记录中的角色 ID 与服装 ID
  恢复，不解析 AI 的回复来决定角色。重开应用后沿用已保存的记录；清空聊天即清除这份连续性。
  明确的新主体 / 新角色不沿用；最新画面没有角色关联时不越过它复活更旧的角色。
  切换角色或明确不用角色库后，空模型回复也不会回收上一角色的旧提示词去出图。
  旧对话没有结构化记录时，仅用上一张画面前用户明确登记的名称 / 别名兼容恢复。
- 请求同时提供可用角色的“登记名称 / 手填别名”索引和本轮已关联档案，明确其它条目未被选择。
  未登记的称呼不由 App 自动认作某个角色；索引不是让模型任选的候选卡。
- 本轮命中用户角色档案后，按需安装的离线大词库只提供普通画面标签，不再混入
  另一套角色身份 / 译名候选，避免同名或机翻候选盖过用户登记的别名和自定义触发词。
  仅在查词用的副本中排除已关联名称 / 别名，避免大量同名身份和衍生词挤占场景词名额；
  发给模型的本轮原文保持不变。
  未使用用户角色档案时，离线角色查询仍照常保留。

### 身份与服装分开

编辑页保留原来的角色触发词 / 外貌，新增别名、调用设置和服装预设。
每个角色可保存多套“服装名称 + 触发词”，选择一套默认，也可不指定默认。
例如登记“冬装：winter_token, coat, scarf”，对话中使用“星澜穿冬装”即可匹配。
点名另一套时覆盖默认；续改保留已选服装，也可明确“恢复默认服装”。指定未登记的新衣服时转为本轮自定义，
下一轮换背景也不悄悄恢复默认服装。多人按照对应名字关联各自服装，不把服装全局拼在一起。

**固定触发词（可选）**只填写必须原样保留的模型关键词。单角色提示词非空时，
App 在解析后、工作流写入前补齐遗漏的固定词和已选服装词；不会把整段旧外貌追加回来，
不补固定反向、不制造空回复的提示词，不增加 AI 请求。已有权重、LoRA 语法与图中文字保留。
单角色切换服装时只清理已登记其它服装的完整独立词项，共享词和明确要求保留的词保留；
自然语言句子不做子串删改，用户要求不补词时照做。
多人不做全局机械补词或删词，交由已按角色绑定的资料和分镜处理；这不是语义识别保证。
固定词补齐后仍使用原有正反向冲突校验，不会为了通过校验静默改掉用户的反向。

回复下方显示实际关联的角色 / 服装，以及真正补齐或清理的词数，不声称 LoRA 已加载。
该库只提供提示词，LoRA 文件仍须由工作流节点实际配置。

角色列表增加名称 / 别名搜索，姓名与操作分行，不再用一排小图标挤掉名字。
编辑页统一滚动、取消 / 保存固定在底部；服装操作先留在草稿，
点击“保存角色”一次落盘，取消整页不保存。删除角色需确认，不影响服务器模型文件。
旧角色资料、开关、按本地 / 云端作用域保存及配置备份继续兼容；
从模型选择器重新导入触发词不会抹掉别名、服装、固定词或常驻设置。
原有人设、分镜和离线词库不改写，本批无需更新 Bridge。

本批 debug APK 构建和 **112 套 / 731 项 Android 测试**通过，新增 48 项。
同一真实 ViewModel / SSE / 工作流回归先在旧实现复现续改未注入档案，再在新实现通过，
两轮请求和提交数不变。覆盖实际工作流触发词、服装切换 / 排除、模型自报 ID 不参与选档、
空回复不复用另一角色、全量可选词库身份隔离、偏好 / 备份和编辑草稿操作。
已检查深色 360dp、浅色 320dp / 1.3 字体倍率原生渲染。测试使用本地模拟服务，

## 0.0.30 上下文与单次输出长度

入口：**Agent 设置 → 模型 API 配置 → 上下文与输出长度**，编辑后点“保存并应用此配置”。
每套配置独立保存，聊天、提示词扩写、自动出图使用同一套本轮冻结设置。

- **上下文预算（tokens）**：可留空或输入 1024–2,000,000，提供 16K / 32K / 64K / 128K
  快捷选择。这是 App 的输入裁剪预算，不是向服务端声明或扩大模型真实上下文窗口。
  按 UTF-8 字节数加消息开销保守估算，图片每张预留 4096；不是具体模型 tokenizer。
  预算包含系统规则、本轮输入、参考资料、历史与输出预留，真实计数仍以服务端为准。
- **单次输出上限（tokens）**：可留空或输入 128–1,000,000，仅发送所选的
  `max_completion_tokens`（默认）或 `max_tokens`（旧兼容服务）。不同时发送两种字段，
  也不发送虚构的 `contextTokens` API 参数。新参数可能同时计入可见输出与思考 token。
- 上下文预算必须大于输出预留；没有指定输出上限时，App 为预算估算预留 4096，
  但请求仍不发送输出上限，实际跟随服务商默认。字段留空不是无限长度。
- 设置预算后最多选最近 200 条有效历史，从最早完整用户/助手轮次开始移除。
  系统规则、当前指令、词库候选和工作流参考保留整段；这些固定内容仍超预算时明确报错，
  不截断当前指令、不丢失正反向参考、不偷偷再发一次请求。
  未设预算时沿用聊天最近约 20 条、画图 4 条的历史数量限制。
- 输入非整数、超范围或输出预留不合适时显示具体提示，禁用保存；旧配置无需重新填写。
  每个请求使用发送时的配置副本，切换配置不让正在结束的旧请求覆盖新设置。
- 服务端不支持所选字段或上限时报告实际错误，不自动降级或重试。原有长度截断提示继续保留。
  App 填入更大的数字不会使服务商模型获得更大上下文或输出能力。

参数核对：OpenAI Chat Completions 官方参考（2026-10-18）：
https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create
未调用用户的付费模型；请求体、裁剪和出图链路使用本地 HTTP 夹具验证。

## 内核职责

- `agent/AgentSessionController.kt`：实例级 `AgentSessionState` / `AgentTurn`；
  发送前同步占用 busy、唯一请求身份、阶段与结束状态，避免连点重复发送。
- `agent/AgentConversationRunner.kt`：生成回复 → 应用提示词 → 可选提交三个步骤；
  `AgentDrawExecutor` 不负责调用 LLM，生成提示词本身也没有提交副作用。
- `ui/MainViewModelAgentRuntime.kt`：每个 ViewModel 的 Android 适配器，负责消息、
  附件、工作流加载、偏好设置和现有本地/RH 提交路径。
- `data/LlmClient.kt`：按 ID 管理实际 OkHttp Call；结束释放索引；协程取消绑定请求；
  连接/读取超时与 240 秒总时限分开报告；空流、格式异常、截断不再触发静默重发。
- `agent/AgentTool.kt`：typed `AgentTool` 接口及 `inspect_workflow`、`patch_workflow`。
  目前供内核调用，不要求模型支持原生 tool calling，也不把模型文字当任意命令执行。

`patch_workflow` 先整体校验再复制修改，返回字段 diff。修改能力来自提示词节点、
本轮图像节点和用户勾选的辅助参数；未知字段、连线、类型、范围和枚举错误使整批修改失败，
失败后不提交。`class_type`、节点拓扑和其他字段保持不变。

停止、清空聊天、切换服务器/模型配置/模板会使旧轮次失效；流式回调、最终结果与清理都按
turn ID 校验，旧任务不会覆盖新会话。独立的模板异步加载还有上下文代次和载入票据，
避免慢文件读取覆盖新模板。消息列表原子更新，进度刷新节流并在最终结果完整落盘。

**停止的边界**：停止本轮 LLM 和尚未提交的步骤；已被 ComfyUI / RunningHub 接收的任务
可能继续执行，本批没有新增远端任务取消工具。
