## 0.0.30 上下文与单次输出长度

入口：**Agent 设置 → 模型 API 配置 → 上下文与输出长度**，编辑后点“保存并应用此配置”。
每套配置独立保存，聊天、提示词扩写、自动出图使用同一套本轮冻结设置。

- **上下文预算（tokens）**：可留空或输入 1024–2,000,000，提供 16K / 32K / 64K / 128K
  快捷选择。这是 App 的输入裁剪预算，不是向服务端声明或扩大模型真实上下文窗口。
  按 UTF-8 字节数加消息开销保守估算，图片每张预留 4096；不是具体模型 tokenizer。
  预算包含系统规则、本轮输入、参考资料、历史与输出预留，真实计数仍以服务端为准。
- **单次输出上限（tokens）**：可留空或输入 128–1,000,000，仅发送所选的
  `max_completion_tokens`（默认）或 `max_tokens`（旧兼容服务）。不同时发送两种字段，
  也不发送虚构的 `contextTokens` API 参数。新参数可能同时计入可见输出与思考 token。
- 上下文预算必须大于输出预留；没有指定输出上限时，App 为预算估算预留 4096，
  但请求仍不发送输出上限，实际跟随服务商默认。字段留空不是无限长度。
- 设置预算后最多选最近 200 条有效历史，从最早完整用户/助手轮次开始移除。
  系统规则、当前指令、词库候选和工作流参考保留整段；这些固定内容仍超预算时明确报错，
  不截断当前指令、不丢失正反向参考、不偷偷再发一次请求。
  未设预算时沿用聊天最近约 20 条、画图 4 条的历史数量限制。
- 输入非整数、超范围或输出预留不合适时显示具体提示，禁用保存；旧配置无需重新填写。
  每个请求使用发送时的配置副本，切换配置不让正在结束的旧请求覆盖新设置。
- 服务端不支持所选字段或上限时报告实际错误，不自动降级或重试。原有长度截断提示继续保留。
  App 填入更大的数字不会使服务商模型获得更大上下文或输出能力。

参数核对：OpenAI Chat Completions 官方参考（2026-10-18）：
https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create
未调用用户的付费模型；请求体、裁剪和出图链路使用本地 HTTP 夹具验证。

## 0.0.29 反向提示词依据与冲突检查

- AI 仍独立编写正向、反向；`negative_prompt` 字段必填，但没有可靠排除项时允许空字符串。
  不再要求“主动写完整反向”而诱导凑词。缺失字段继续保留工作流原值，明确空字符串继续清空。
- 依据顺序为本轮用户排除/保留/清空要求、工作流仍适用的已有反向，再到少量有依据的相关缺陷词。
  历史 AI 反向和负面词库命中均只作候选；不凭空编造 embedding、LoRA、模型专用词或权重。
  提醒模型检查柔焦、胶片颗粒、单色、图中文字等用户要求是否被通用反向抵消。
- 生成前从同一只读模板副本同时取得原有反向和已配置的 checkpoint、UNet、CLIP、LoRA 文件字段，
  以 JSON 数据提供参考，不额外联网、不读模型权重、不根据文件名宣称已确认模型能力。
- 写入独立反向字段前检查完全相同的标签，兼容大小写、下划线/空格与简单注意力权重。
  例如正向 `(red eyes:1.2)` 与反向 `red_eyes` 会显示具体冲突，保留模型输出供查看，
  该轮不改写正反向字段、不提交出图；让用户调整要求后重试，而不是静默删除任一侧。
  这是字面标签校验，不做子串、同义词或任意自然语言语义推断，不承诺发现所有不合理反向。
- 选择“保留工作流原值”或没有独立反向输入时，未应用的 AI 反向不阻止提交，仍明确显示写入状态。
  无新增模型请求、自动重试或固定反向模板。仅升级精确匹配上一版默认分镜的保存文本，
  在本地留旧副本；用户自定义人设和分镜保留，新依据规则由应用契约一并提供。

0.0.28 的全量 ai-tag-toolbox 词库继续保留：10 份原始数据、242,959 项唯一条目，
其中 240,851 项有中文，2,108 项上游缺中文时明确标注；详见 [TAG_LIBRARY.md](TAG_LIBRARY.md)。

## 内核职责

- `agent/AgentSessionController.kt`：实例级 `AgentSessionState` / `AgentTurn`；
  发送前同步占用 busy、唯一请求身份、阶段与结束状态，避免连点重复发送。
- `agent/AgentConversationRunner.kt`：生成回复 → 应用提示词 → 可选提交三个步骤；
  `AgentDrawExecutor` 不负责调用 LLM，生成提示词本身也没有提交副作用。
- `ui/MainViewModelAgentRuntime.kt`：每个 ViewModel 的 Android 适配器，负责消息、
  附件、工作流加载、偏好设置和现有本地/RH 提交路径。
- `data/LlmClient.kt`：按 ID 管理实际 OkHttp Call；结束释放索引；协程取消绑定请求；
  连接/读取超时与 240 秒总时限分开报告；空流、格式异常、截断不再触发静默重发。
- `agent/AgentTool.kt`：typed `AgentTool` 接口及 `inspect_workflow`、`patch_workflow`。
  目前供内核调用，不要求模型支持原生 tool calling，也不把模型文字当任意命令执行。

`patch_workflow` 先整体校验再复制修改，返回字段 diff。修改能力来自提示词节点、
本轮图像节点和用户勾选的辅助参数；未知字段、连线、类型、范围和枚举错误使整批修改失败，
失败后不提交。`class_type`、节点拓扑和其他字段保持不变。

停止、清空聊天、切换服务器/模型配置/模板会使旧轮次失效；流式回调、最终结果与清理都按
turn ID 校验，旧任务不会覆盖新会话。独立的模板异步加载还有上下文代次和载入票据，
避免慢文件读取覆盖新模板。消息列表原子更新，进度刷新节流并在最终结果完整落盘。

**停止的边界**：停止本轮 LLM 和尚未提交的步骤；已被 ComfyUI / RunningHub 接收的任务
可能继续执行，本批没有新增远端任务取消工具。

## 0.0.6 本地词库与双向提示词

### 提示词职责和格式

入口：**Agent 设置 → 提示词格式与本地词库**。

- 人设只定义 reply 的语气和对话职责；不把口癖放进提示词、不虚构生成状态。
- 分镜负责编写画面内容、主体属性归属和反向排除项。每次独立分析并输出
  `prompt` 和 `negative_prompt` 字段；反向可空，不由 App 附加固定反向模板。
- 反向按本轮需求和模型编写，不和用户明确要求的主体、风格、文字或特征对冲。
  保留适用的模型词、embedding、权重；无排除项、模型不适用或用户要求清空时允许空字符串。
- 外层仍为一个 JSON：`reply`、`prompt`、`negative_prompt`、`should_draw`。
  用户明确只要提示词时不自动提交。

不再设置「通用 Tags / Anima 混合 / 自然语言」固定格式挡位。用户需求、当前模型与自定义分镜共同决定使用 tags、必要的主体/空间绑定短句或自然语言；解析保留引号文字、换行、权重和 LoRA 触发词。正反向仍单独编写、绑定、展示和保存，本地双语词库开关与离线检索保留。
画面选择一个可见定格瞬间，裁剪与可见细节一致；多人避免属性串染，双人不强制左右站位。
本轮改图优先，移除冲突的旧姿态、服装和表情，不扩写无关故事。

借鉴 ai-tag-toolbox 的职责分离、候选词与主体绑定思路，规则重新编写；不照搬它的宿主包装、
强制质量前缀或多子 Agent 循环。外部资料中的 XML、代码块和“只输出正文”不会替换 App 的 JSON 契约。
用户自定义人设和分镜保留；仅指纹完全匹配旧内置默认规则时升级，并在本地偏好保存旧副本。

Agent 设置分为模型服务、提示词、可选资源。模型连接与生成参数分别展开，保留配置切换、
思考强度、上下文和输出长度；长说明按需展开。提示词显示简短预览，编辑与取消保留原有
对话框退场动画。连接参数点击保存；词库开关立即保存，反馈统一使用系统 Toast。

绘图前从本轮要求精确检索有限候选，再发起**一次**模型请求，不要求原生 tools，
不为查词增加第二轮模型修订。0.0.6 的对话可展开离线候选；
0.0.7 已按反馈去除这个状态面板，后台候选仍只供参考。
未命中或读取失败保留用户原始要求、自定义词与模型语法，不将未知词判为无效。
本地查词本身不调用 AI；生成提示词仍使用用户配置的模型服务。

### 正向 / 反向节点分别设置

入口：**Agent → 选择工作流 → 设置节点**。两个标签页分别配置：

- 正向：自动探测，或指定 `#节点:字段`。
- 反向：自动探测、指定 `#节点:字段`，或保留工作流原值。
- 同节点的两个不同字符串字段可分别绑定；同一个字段不得同时承载正反向。
- 不把连线、图像或数字槽列为提示词字段。显式绑定失效时显示具体错误，不悄悄猜另一个节点。
- 配置按本地/云端作用域、工作流来源和工作流 ID 分开保存；兼容旧的正向 nodeId 配置。

自动反向仍沿 conditioning 连线识别，支持 SDXL 两个文本槽、链接文本节点、独立反向字符串和明确标题。
避开共享正向以及 ConditioningZeroOut 上游，不改连线。显式选择时只写用户选定字段。

生成前只读模板副本，按所选反向字段和已存参数提供参考，不提前修改活动工作流。
模型遗漏、null 或无效反向字段时保留原值；明确空字符串则清空。
找不到独立反向输入时仍显示生成的反向，并标明“未写入”。保留原值模式也明确区分“生成”与“已应用”。

### 双向展示、复制和保存

底部 **出图提示词** 弹窗同时展示正向和反向，可“复制正向 / 复制反向 / 复制两组”，
显示写入状态。两组词用同一条记录成对保存，重新打开仍可查看；旧数据只存正向时不伪造旧反向。
对话气泡仍可展开两组词；最近一轮正向和反向一起回传给模型，改图保持连续性。
清空聊天同步清除本轮成对记录。

### 验证边界

回归覆盖真实打包词库、别名、中英文、负面词分类、角色隔离、配置迁移、单次模型请求、
精确双向字段写入、KEEP、无效绑定、缺失/空反向、成对保存和 Compose 展示/复制点击。
本地 HTTP 夹具模拟模型及 ComfyUI；没有调用付费模型、实际出图或自动安装 APK。
