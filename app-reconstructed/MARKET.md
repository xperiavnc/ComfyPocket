# 集市第一阶段

## 手机侧

- 默认手机直连 Civitai，无需电脑在线即可搜索、筛选和查看详情。
- 独立 `MarketViewModel`、网络客户端和搜索状态控制器，不继续扩充主 ViewModel。
- 集市右上角设置中可切换手机直连 / 电脑桥接，配置手机 HTTP 代理、
  可选代理认证和 Civitai Key。
- Key 与代理密码由 Android Keystore 加密，排除在普通配置导出之外。
  正常校验 Civitai TLS，不继承本地 ComfyUI 连接的证书例外。
- 列表、模型和版本元数据 5 分钟缓存；断网可显示过期缓存，
  401 / 403 / 404 不用旧数据掩盖访问拒绝。
- JSON 缓存按来源、账号和内容级别分区，最多 60 条 / 16 MiB；
  图片缓存 96 MiB，代理热切换会作用于后续图片请求。
- 搜索取消旧请求并检查代次；分页按模型 ID 去重，加载更多不会混用输入框的新草稿。
- 模型简介、版本说明、触发词和预览图可查看；API 有图片元数据时显示对应的
  正向/反向提示词和参数，可复制。补充的社区示例与作者预览明确分开，
  缺少提示词时直接说明，不生成或猜测。
- HTML 简介以惰性文本展示，不执行脚本。长内容整体滚动，下载栏保持可见。

## 联动电脑

手机浏览 Key 不等于电脑下载 Key。电脑下载需要配套 Bridge 2.0：

**ComfyUI 设置 → Mobile Bridge → Civitai → Civitai Key（电脑端下载）**

安装、服务端 Key 存储、代理、原生队列和回退见
`ComfyUI-Mobile-Bridge/README.md`。

手机的版本 / 文件 / 目录选择继续保留；电脑用官方文件 ID 重新验证下载。
手机与电脑可使用不同账号，手机匿名浏览的 `canDownload` 不阻止电脑再次验证权限。
手机未列出文件时，按钮明确说明由电脑按所选版本选择主文件。
新增下载队列弹窗，只在弹窗可见、应用前台且已连接电脑时轮询，
支持暂停 / 继续 / 取消。旧插件缺少 `native-*` 接口时明确提示更新。

Key 只提供账号原有的访问权限，站点内容级别、购买/抢先体验和地区限制仍然生效。
某个版本出现在列表里不保证当前账号具备下载权限。

## 未改动与验证边界

- 不改底部导航、切换动画或其他页面的工作流编辑状态。
- Bridge 是单独安装的 Python 插件，不打包进 APK；升级需替换整个插件目录并重启。
- Android 的常规 ComfyUI 连接仍沿用原有证书策略，本次只给 Civitai 直连使用独立
  正常 TLS 客户端，不宣称已修复应用所有网络策略。
- 自动化测试覆盖 JSON、代理、TLS、缓存、搜索竞态、原生下载路由、Key 设置和队列。
  本地浏览器烟测使用模拟 Key；不等价于真机、真实 Key、真实代理或付费模型下载验收。

## 分类与连续浏览修正（2026-10-17）

- 大模型对应 Civitai 的 Checkpoint，UNet 对应官方独立的 UNet 类型；GGUF 在 Checkpoint/UNet 中按模型文件的 GGUF 格式筛选。VAE/文本编码器的 GGUF 文件不会被当作主模型。
- 筛选结果只展示匹配基础模型的版本；GGUF 详情优先选择对应 GGUF 主文件，仍保留版本所需组件。一个模型同时提供多种格式时，可以出现在多个相关分类中。
- 不再固定 earlyAccess=true：该参数是“仅抢先体验”过滤，不是“允许受限模型”。访问权限仍取决于手机/电脑各自配置的 Key，原有凭据不变。
- 每页 20 个不是总数量上限。接近列表底部自动用官方游标续页，也可手动“加载更多”；空的过滤页仍可续页，重复游标停止以防循环。网络失败保留已加载结果并提供重试。
- 搜索缓存升级为 search-v2，旧版错误分类和仅抢先体验缓存不会复用。
- 集市返回按钮与系统返回共用单次退栈门控；弹窗打开时由弹窗处理返回。集市没有上一页时回到应用主页，不留下空 NavHost。该门控尚未解决用户反馈的真机手势退出问题，函数单测通过不代表真机修复。
- 电脑桥接模式的分类修正需要完整更新 Bridge 2.0.1 并重启 ComfyUI；手机直连不依赖电脑插件。

## 集市返回诊断（2026-10-17）

`0.0.1-return-diagnostic`（versionCode 2）用于定位“返回一次就到桌面”，
不是已经确认解决该故障的版本。不继续叠加返回防抖，不更改退栈策略、预测式返回开关、
底栏或切换动画。

1. 安装诊断包后进入集市，复现一次返回故障。
2. 如果退到了桌面，重新打开应用；进入应用的 **设置 → 导出返回/退出诊断**。
3. 选择保存位置，把生成的 `ComfyPocket-return-diagnostic-*.txt` 用于排查。

报告保留最近 200 条页面返回、目的地、页面/Repository 销毁及 Activity 生命周期事件。
Java 异常只记录类型和栈帧，不记录异常消息；系统退出历史可区分 Java crash、
native crash、ANR、低内存及用户退出。系统历史可能包含旧记录，应核对时间。
报告不包含配置、Key、代理密码、请求 URL、模型名称、提示词或系统原始崩溃转储；
只在用户选择导出时生成报告，不自动上传。

新增 Robolectric + Compose 集成测试使用真实 MainActivity、NavHost 和集市页面，
覆盖完成/取消返回、工具栏返回与重入、弹窗优先及后台恢复。
使用 legacy graphics，因为测试运行库的 Skia 不支持 Miuix 使用的 AGSL `layout(color)`；
这类测试不验证手机 GPU、系统手势驱动或厂商 ROM，仍需真机退出记录。

## 集市返回时 TLS 清理崩溃修复（2026-10-17）

`0.0.1-market-return-fix`（versionCode 3）针对诊断确认的 Java 崩溃：
页面已经返回首页，但随后 `MarketViewModel.onCleared()` 同步调用连接池清理，
Conscrypt 关闭 TLS 连接时发送数据，触发 `NetworkOnMainThreadException`。
这不是同一次手势退栈两次；本批不改返回门控、预测式返回、底栏或切换动画。
诊断原件和构建证据仅留本地，不提交仓库。

- 资源清理统一由独立的进程级 IO 工作线程执行，不依赖已经取消的 `viewModelScope`。
- 关闭图片加载器、取消请求、关闭本集市客户端的调度器并等待其结束，
  然后驱逐连接池；不关闭跨页面共享的磁盘图片缓存。
- 保存代理/Key 会立即替换客户端，旧客户端后台回收；最终关闭会等待此前的轮换清理。
  重复关闭复用同一完成结果；已经关闭的 Repository 不再接受设置变更或新直连请求。
- 单项清理失败仍继续处理其余资源，并记录固定失败事件，不记录异常消息或凭据。
  `MARKET_REPOSITORY_CLOSED` 只在所有清理完成且成功后记录，失败则记录
  `MARKET_REPOSITORY_CLOSE_FAILED`，不把“已排队”等同于“已关闭”。
- 新增 10 项回归：真实回环 HTTPS 建连并复用后，从 Android 主线程触发关闭或设置轮换；
  还覆盖已取消 ViewModel scope、关闭幂等性、连续轮换、运行/排队请求取消和清理异常隔离。
  原版本在两项暖连接回归中抛出同一 `NetworkOnMainThreadException`，修复后通过。

测试在 Robolectric API 35 上使用真实 HTTPS 连接。桌面 TLS 不具有 Android Conscrypt
的主线程网络检查，所以测试仅在已暖连接的 close 句柄增加该检查；证书校验仍开启，
测试证书只对回环地址信任。它验证了清理线程与生命周期，但不是手机原生 TLS、
手势驱动或厂商 ROM 的端到端验收。安装后应先加载集市图片，再手势返回并反复进出，
同时检查保存代理/Key 和导出诊断的关闭完成事件。
