# Agent 页面信息密度优化：设计研究与同尺寸交互预览

日期：2026-10-27（Asia/Shanghai）

## 本轮交付范围与证据边界

本轮根据用户提供的 Agent 页面截图制作两种可交互布局，并重写设计任务。
Android 应用源码、版本号、Gradle 配置与 APK 均未修改。
本轮没有读取真实对话、连接凭据、工作流文件或设备日志，也没有把用户截图复制到仓库。
预览中的山峦是 CSS 绘制的示意图，对话文案为设计样例。
`16%`、`K采样器`、`安卓anima`、反向词六条释义、写入工作流一项以及五个导航名称来自截图。

`agent-page-density.html` 是供 Codex visualize 渲染的 HTML 片段。
宿主负责方案轮播、图标与可选外观控件；该片段不连接生成服务。
预览点击只更新页面内示例状态，不改变真实 Agent 设置或会话。
`agent-page-density.check.js` 是通过 Playwright CLI 执行的浏览器验证，不是 Android 原生测试。
实际执行结果见 `agent-page-density-verification.json`。

## 从截图可以确认的问题

1. 图片、巨大居中的生成状态、进度和图片底部配置入口同时争夺注意力。
2. 反向词英文、中文释义与工作流写入结果占据较大的常驻区域，并与消息输入框共用外层容器。
3. 会话入口、Chat/绘图、`dsh`、删除和页面设置分散在不同位置，任务层级需要重新明确。

这些观察支持重新组织界面，尚不足以证明某个入口低频或多余。
截图中的英文顶部被截断可能是滚动位置造成的，不能仅凭截图认定为布局故障。
`dsh` 的业务语义、顶部设置的配置范围、模式切换对生成任务的影响，均需结合原始代码和实际操作核实。
预览保留这些入口，页面设置与绘图设置分开呈现。

## 高水平设计研究还应完成的工作

- 先确定用户主要在完成哪个任务：看图与迭代、编辑配置，还是通过 Agent 连续对话。
- 根据实际使用行为确定信息常驻、摘要与按需展开的层级，而非依据设计者偏好删控件。
- 明确会话、模式、配置、当前任务与结果的关系，并核实界面文字背后的真实状态。
- 对空白、输入中、生成中、成功、失败、重连、长文本、软键盘与大字体等情况建立状态表。
- 同时验证“容易找到”和“少占空间”，观察信息折叠是否增加查找时间或操作失误。
- 在设计前记录基线任务、测试条件与验收指标，避免只凭视觉偏好宣布改善。

## 两种方案与取舍

### 生成优先

将会话切换收进顶部标题区；将 Chat/绘图作为工作区。
图片保持主要位置，生成状态放在图片下方，用同一行显示任务、阶段与进度。
安卓anima、画风/画师和提示词聚合到绘图设置入口。
反向词更新只常驻摘要，六条释义通过详情面板查看。
清空操作收进会话菜单，并提供确认。

适合主要在看图、调整与等待生成的任务。取舍是阅读完整对话需要切换工作区。

### 对话优先

在会话时间线上显示简短执行结果，把当前生成任务放进小型任务卡。
任务卡保留进度、阶段和预览入口。
Chat/绘图作为输入模式放在输入框附近，绘图设置与 `dsh` 保持同一上下文。

适合持续用自然语言驱动 Agent 的任务。取舍是查看大图需要额外打开预览。

两方案默认均显示生成中 16%，宽 400 CSS px 时均高 882 CSS px（含外框）。
它们使用同一示意图与相同的功能名称，避免通过更换内容或扩大画布制造差异。

## 证明改善所需的独立证据

### 本轮已完成

- JavaScript 语法检查通过，HTML 片段没有文档外壳或错误的转义换行。
- 两方案 × 深浅色 × 320/360/400 CSS px，共 12 组首屏几何检查通过。
- 已检查的结构区域无横向溢出，按钮未越过手机边界，输入区未与导航重叠。
- 可见产品按钮至少 48 × 48 CSS px；两种布局常规首屏高度一致。
- 两方案均通过反向词详情、六条释义、背景 inert、对话框标签、Escape 与焦点返回检查。
- 绘图设置编辑保存、模式切换、预览、发送按钮、回车发送与清空确认均通过。
- 深浅色首屏及详情面板截图已人工查看。

原生表单提交在预览沙箱中受到拦截，交互检查发现后已改用页面内点击与回车处理。
最后一轮验证通过后才保存本结果。检查脚本等待 iframe 完成尺寸变化后再读取实际几何数据。

### 待正式 Android 实施后完成

- 真机键盘、大字体、横屏、系统栏、TalkBack 与原生触控面积。
- 空白、失败、断连、长历史和无预览等状态。
- 原有模式、配置、会话和任务行为的功能回归。
- 目标用户对照测试，包括被折叠信息的发现率、额外点击、耗时与误触。

### 建议预先约定的验收目标

以下是设计目标，不是本轮实测的 Android 结论：

- 常规生成状态下，当前任务、进度和输入入口无需展开即可辨认。
- 从主页面查看反向词详情不超过一次点击，进入绘图设置不超过两次点击。
- 用户理解当前任务和找到关键入口的成功率不下降；任务耗时与误触改善需由对照测试确认。
- 核心功能清单逐项可达，折叠或迁移均有新路径，删除有确认或可撤销机制。
- 已支持设备、大字体与键盘状态下没有关键内容遮挡、溢出或操作丢失。

“正确”在这里指特定任务和设备条件下有可重复证据的改善，不代表存在唯一审美答案。
独立用户、原生工具、可复现操作与原始日志分别支持体验、可访问性、布局与业务状态的结论。

## 重写后的完整题目

请对 ComfyPocket 的 Agent 页面进行一次基于原始证据的移动端信息架构与交互重设计，并渲染同尺寸可交互示例。

目标是在保留现有核心能力的前提下，降低视觉竞争、找控件的成本与误触，让用户明确当前任务、执行状态和下一步操作。请先解释拥挤产生的机制，再提出布局。控制方案范围，优先解决这张页面的核心问题。

1. 首先从原始材料核实现状：对应版本的 APK 与界面源码、真实设备尺寸/density/font scale、完整任务录屏、界面层级与生成事件。材料缺失时列出缺口，明确标注截图可确认的事实、推断与待验证项。
2. 确定目标用户和前三个主要任务；使用实际操作频率与任务路径判断每个入口的重要性。核实 Chat/绘图、dsh、页面设置、绘图配置、会话和任务之间的业务关系，建立完整功能清单与状态表。
3. 分析视觉竞争、重复信息、层级、控件分组、滚动、错误风险与可访问性。每项主要问题都说明原始证据、影响的任务和可证伪的改进假设。
4. 提供两种结构不同、可落地的方案：生成预览优先、会话任务卡优先。说明各自适用场景、取舍、关键入口路径与推荐依据；推荐依据不足时如实说明。
5. 首屏突出当前任务、进度与输入操作；把详细释义和执行记录转成可发现的摘要与详情；按任务组织配置入口。明确迁移后的会话、清空、页面设置与 dsh 路径，保留原有核心功能语义。
6. 两方案使用相同的设备可用区域、内容、生成状态与字体基线进行比较。保留现有产品视觉特征和五个底部导航入口。优先通过信息层级与交互组织改善空间利用，控制缩字、隐藏、额外步骤与画布变化带来的偏差。
7. 提交可交互预览：至少演示模式切换、配置查看、反向词摘要展开、图片预览、消息输入与清空确认。指出示意内容和真实业务连接的边界。
8. 原生设计以至少 48 × 48 dp 的触控目标为要求，覆盖常用窄屏、系统大字体、软键盘、空白、生成中、成功、失败、断连和长文本。截图像素和网页 CSS px 不直接视为真机 dp。
9. 在测试前约定验收标准：生成进度与输入首屏可见；查看反向词详情不超过一次点击；进入绘图设置不超过两次点击；核心功能逐项可达。以目标用户的任务完成率、耗时、误触和信息发现率作对照，避免仅以美观判断优劣。
10. 提供独立证据：同条件的基线/改版操作、截图或录屏、可复现步骤、工具检查与未参与设计的目标用户记录。区分已验证、原型范围内验证和待真机验证；记录失败、代价与剩余风险，使用官方规范和一手研究解释关键决策。
11. 最终交付问题诊断、原始材料清单、方法与工具、两种可交互方案、推荐和取舍、验证记录与实施优先级。遵循本地 AGENTS.md 的 Git 备份及 APK 命名约定，实际执行到哪一步就报告哪一步。
